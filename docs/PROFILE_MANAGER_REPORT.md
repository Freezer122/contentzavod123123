# Profile Manager V1.8

В Telegram: «Аккаунты → аккаунт → Профиль». Доступны текущее био/ссылки, обновление из Threads, ручное био, генерация био, добавление/изменение/удаление ссылок, предпросмотр, подтверждение и DRY_RUN. Изменения сохраняются через AdsPower/Playwright, без отдельного Threads API.

Используется фактический редактор Threads 02: вложенный Bio/textarea и Links/URL. Поддерживается до пяти ссылок при наличии интерфейса добавления. Такой предел [описан Meta](https://about.fb.com/news/2025/03/new-threads-features-more-personalized-experience-you-control/); недоступные элементы или неоднозначные поля приводят к остановке.

Снимки, черновики, статусы и hash предпросмотра хранятся в существующей PostgreSQL-таблице system_settings с отдельными префиксами; действия — в audit_log. Это использует текущий repository и serializable transactions без переписывания рабочих таблиц. Перед первым save повторно проверяются исходный снимок и одобрение. Состояние SAVING записывается до клика; ошибка после него переводит изменение в UNCERTAIN и запрещает автоматический повтор. После успешного save поля заново читаются из интерфейса.

По умолчанию `PROFILE_CHANGES_ALLOWED=0`. Кнопка выполняет проверку без сохранения: введённое поле восстанавливается и редактор отменяется. В LIVE дополнительно нужны разрешение оператора на включение и подтверждение конкретного предпросмотра. Никакие реальные изменения в рамках этой работы не выполнялись.

## Проверено

На настоящем Threads 02 выполнены BIO, ADD_LINK, EDIT_LINK и DELETE_LINK в DRY_RUN. Все четыре сценария успешны. Hash био/ссылок до и после совпал: `e34bdf7aa91ac032cfc89b0d0a1074d69c9ca7dcb688376338ff4fe3e003b451`. Сохранений профиля: 0; браузер закрывался после операций. Thread 01 не использовался.

Автоматические проверки: точное одобрение, лимит ссылок, запрет повтора после UNCERTAIN, ручной ввод без LLM, Telegram-меню, восстановление полей без save на браузерной HTML-фикстуре.

## Нормализация и ИИ

TextNormalizer реализован в TypeScript и включается отдельно для аккаунта. По умолчанию выключен. Обрабатывает регистр, окончания абзацев, emoji, тире, zero-width/NBSP/BOM и пробелы. Защищает URL с query, регистрозависимые идентификаторы, тикеры и финансовые числа. Unicode-тесты и идемпотентность проходят. Уже одобренные тексты и опубликованная история не изменяются; ручная правка создаёт новую неодобренную версию.

Обычная адаптация сохраняет прежний кэш, когда нормализация выключена; при включении версия нормализатора входит в cache key. Для COMMON требуются одинаковые настройки нормализации выбранных аккаунтов. Стили, шаблоны, библиотека и журнал качества сохранены.

Ручное био не вызывает модель. Генерация био использует существующий бюджетируемый ContentEngine, один запрос, кэш и назначение BIO. Ответы используют REPLY, посты — POST. До запроса резервируется стоимость; дневные/месячные лимиты проверяются глобально и для аккаунта/назначения. В меню доступны бюджеты постов, био и ответов. Shared-request затраты делятся по аккаунтам.

На настоящем VPS LLM не настроена; платные генерации не выполнялись. Провайдер проверен стабами, повторная генерация того же входа использует кэш. Для первой платной генерации нужны ключ, модель и цены.

## CTA

Существующий Telegram-интерфейс текста/ссылки/состояния сохранён. Добавлена загрузка изображения, предпросмотр привязки и её удаление. Файл хранится в приватном media, проверяются формат/размер/realpath/SHA256, версия CTA увеличивается. Новая задача получает неизменяемый снимок вложения; уже отправленные задачи не изменяются. Старые вложения исторических jobs сохранены. Удаление привязки не удаляет пользовательский файл.

Требует отдельного реального теста после разрешения: сохранение изменённого био/ссылок и подтверждение итогового UI. В DRY_RUN путь save намеренно не нажимался.

Итоговый общий набор на VPS: 106 тестов прошли, отдельный PostgreSQL/Redis сценарий также прошёл. Новый save в настоящем Threads намеренно не выполнялся.
