# Content Factory — правки перед запуском, V1.2

Дата: 18 ноября 2026. Изменения внесены в существующий проект. VPS, AdsPower, Webshare и реальные Threads-аккаунты не подключались. Реальных публикаций и запросов паролей/почтовых кодов не было. Все проверки выполняются на локальных тестовых данных.

## Уже было и что доработано

До этой итерации работали ACCOUNT_SPECIFIC/BROADCAST, пакетная генерация, кэш, очередь с защитой от повторной отправки, независимые статусы поста/CTA, аккаунтная tracking-ссылка, Insights-адаптер, снимки и D7/D30. Эти модули сохранены.

Добавлены библиотека подачи Threads, оценки генераций и DRY_RUN. Изменены правила расписания и применения CTA. Уточнён рейтинг шаблонов и изоляция стилей аккаунтов.

## Готовые функции

- ACCOUNT_SPECIFIC назначает отдельный материал каждому аккаунту; BROADCAST поддерживает общий текст и пакет индивидуальных вариантов. Генерация и очередь создаются только по команде пользователя.
- По умолчанию 10 аккаунтов занимают 12-минутные слоты: старты в 0, 12, …, 108 минут. Последние 12 минут двухчасового окна оставлены под задержки. Для N аккаунтов слот равен 120/N минутам; один аккаунт стартует без межаккаунтного интервала. Следующая ожидающая партия не занимает резерв предыдущей. Сохранённые старые планы автоматически не пересчитываются.
- У аккаунта одна запись CTA, которую можно включать/отключать. В боте: «Аккаунты → аккаунт → Изменить CTA», текст, ссылка, предпросмотр, «Сохранить CTA». Снимок версии фиксируется при первом переходе задачи в выполнение. Правка действует на ещё не начатые задачи; повторные попытки и завершённые задачи сохраняют свой снимок. Отключение CTA не останавливает основной пост.
- Собственный комментарий отправляется не раньше 20 секунд после подтверждения поста. Известная ошибка до отправки — COMMENT_FAILED при успешном посте. Неопределённый результат — UNCERTAIN и ручная проверка; автоматический повтор запрещён.
- Основной промпт адаптирует экспертный X-текст к разговорной подаче Threads: одна мысль, минимум жаргона, без выдуманных фактов и личного опыта. Обычная генерация — один запрос; проверки, оценки, рейтинги, расписание, браузер и когорты обходятся без LLM. Исходник в пакетном запросе передаётся один раз.
- Восемь шаблонов: наблюдение из жизни трейдера, история, вопрос аудитории, провокационное мнение, ирония, ошибка новичка, психология торговли, простое объяснение сложной темы. Есть создание, правка, примеры, закрепление/снятие, версии и статистика.
- Каждый аккаунт получает собственный стилевой профиль. Назначение готового стиля копирует настройки в профиль аккаунта; изменение одного не меняет остальные.
- Кэш учитывает исходник, версию промпта, модель/API, параметры, стиль и версию/примеры шаблона. Ручная перегенерация явно обходит кэш. При отсутствии provenance у старой генерации модель/токены показываются как неизвестные, а не выдумываются.
- Под черновиком есть 👍 «Хорошо» и 👎 «Плохо». Оценка сохраняет исходник, результат, аккаунт, стиль и его снимок, шаблон и его снимок, промпт, модель, request ID, токены и время. Оценку можно изменить. Процент одобренных генераций считается по последней оценке каждого текста. Оценка не равна разрешению публикации.
- В пакетном запросе расход относится к общему request ID и помечен SHARED_REQUEST. Его нельзя суммировать повторно по всем вариантам. Ручная редакция помечается MANUAL_EDIT с нулевыми новыми LLM-токенами.
- Контентный рейтинг содержит сопоставимые отметки 1/6/24/72/168 часов, лайки/ответы/репосты, формат, шаблон, аккаунт и дату. Есть топ/антитоп, средние/медиана/максимум/минимум, темы, форматы и динамика за семь дней. Накопительные значения остаются в общей аналитике; топы сравнивают фиксированный возраст.
- Шаблон включается в основной рейтинг только после 10 своевременных известных замеров одной текущей версии на выбранной возрастной отметке. До этого статистика предварительная. После правки версии старые данные сохраняются, но не доказывают качество новой версии. NULL не превращается в ноль.
- Telegram-атрибуция остаётся аккаунтной. Подтверждённый выход связывается с ранее наблюдаемым эпизодом подписки. Клики, вступления, выходы и неизвестные источники разделены; D7/D30 и Churn показывают покрытие, не выдают позднюю проверку за исторический факт.

## Миграция базы

Новая миграция добавляет три таблицы: `content_templates`, `content_template_examples`, `generation_feedback`. Итого 31 прикладная таблица. Добавлены provenance генераций/кэша, ссылки на шаблоны, персональные стили и момент фиксации CTA. Снято старое ограничение, запрещавшее отключать личный CTA.

Старые генерации, планы, клики, подписки и снимки не удаляются. Для начатых и исторических задач сохраняется существующий CTA; ещё не начатые получают текущий CTA при исполнении. Старые стили остаются для истории; аккаунтам копируются собственные профили и примеры. Seed создаёт четыре готовых пресета и восемь шаблонов.

Команды для локального/будущего согласованного окружения, не выполняющие подключение к VPS сами по себе:

```bash
npm ci
npm run db:migrate
npm run db:seed
npm run check
```

Для реальной БД перед обновлением нужны остановка приложения и резервная копия. В этой итерации миграция проверяется только на временной локальной БД.

## DRY_RUN

По умолчанию `BROWSER_EXECUTION_MODE=DRY_RUN`. В production исполнитель публикаций и проверка реальных профилей отключены; очередь остаётся в БД. В demo все провайдеры заменены MockBrowserProvider. Переход к LIVE — отдельное явное изменение конфигурации после согласованной приёмки.

```bash
npm run dry-run -- OK saved-profile-Threads-02
npm run dry-run -- CDP_ERROR saved-profile-Threads-02
npm run dry-run -- UNCERTAIN_POST saved-profile-Threads-02
```

Без системного Node.js в текущем рабочем каталоге:

```bash
./scripts/run-local.sh npm run dry-run -- UNCERTAIN_POST saved-profile-Threads-02
```

Диагностика не читает конфигурацию реального сервера, не вызывает Browser Local API и не создаёт реальных публикаций. Сохранённый profile_id проходит через Mock-профиль, что проверяет привязку идентификатора без запуска AdsPower. Проверяются запуск, CDP, таймаут, потеря подключения, авторизация, известная ошибка поста/CTA и неопределённые результаты. В боте: «Система → Диагностика DRY_RUN». Внутренний API: `POST /api/diagnostics/browser`.

## Проверки

Основная команда — `npm run check`: форматирование, TypeScript, автоматические тесты и production-сборка. Для полного интеграционного теста нужны отдельные локальные TEST_DATABASE_URL и TEST_REDIS_URL. В тестах используется Chromium с перехваченным тестовым HTML, не реальный Threads.

Проверяются оба режима, кэш, версия промпта/шаблона, журнал оценок и изменение оценки, индивидуальность стилей, 12-минутные слоты и резерв, текущий CTA при старте, отключение CTA, сохранение версии при повторной попытке, сохранение поста при ошибке комментария, порог 10 замеров, одинаковый возраст, D7/D30 и десять диагностических сценариев. В DRY_RUN отдельно проверены отсутствие вызовов fetch, нулевые LLM-запросы и освобождение сессий/блокировок.

## Что требует внешних API и что осталось до Threads 02

1. Отдельно разрешить этап реального теста. Сейчас подключения запрещены и не выполнялись.
2. Проверить легальный доступ к AdsPower Local API на установленной версии и тарифе Free. Код не обходит лицензионные ограничения.
3. Подтвердить сохранённый profile_id именно Threads 02; Thread 01 не выбирать. Проверить ручную авторизацию и Webshare в существующем профиле.
4. На VPS 2 vCPU / 4 GiB / 60 GiB начать с одного исполнителя. Графическая сессия и Local API должны быть доступны; реальное потребление RAM здесь не измерялось. Дополнительное ПО на VPS не устанавливалось.
5. Проверить актуальные селекторы авторизованного Threads UI. Все текущие браузерные тесты локальные; реальный пост/CTA и URL пока не подтверждены.
6. Для реальной адаптации нужны LLM endpoint/модель/ключ и тарифы. Для извлечения X-ссылок нужен X API либо исходный текст вручную.
7. Для Insights нужны разрешения/token и API user ID. Для вступлений/выходов и getChatMember — Telegram-бот с правами в канале и сохранённый TRACKING_HASH_SECRET; для redirect — настроенный HTTPS-домен. Неподключённые метрики остаются неизвестными.

Пароли и почтовые коды на этой стадии не нужны. Вторая LLM, мультиагентная архитектура, ML, автоматическое обучение и ИИ-планировщик не добавлялись.
