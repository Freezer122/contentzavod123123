## Проверка редактора

У пустой кнопки Posten `isEnabled()` возвращает `true`, атрибутов `disabled` и `aria-disabled` нет, а CSS opacity равна `0.3`. Поэтому внешний серый вид кнопки не используется как гарантия блокировки отправки. Тест проверяет пустоту редактора и не вызывает отправку независимо от состояния кнопки.

Первая попытка остановилась на излишнем требовании `EMPTY_SUBMIT_ENABLED`; подключение CDP, авторизация и открытие редактора уже работали. После замены этого требования записью фактического состояния DOM полный тест завершился успешно. В обеих попытках профиль был штатно закрыт.

## Повторный запуск

Добавлена команда `npm run probe:adspower`, код — `scripts/probe-adspower.ts`. Она проверяет точное имя профиля и отсутствие уже активных профилей на этом хосте. Подключение использует существующий `AdsPowerProvider`; действия внутри Threads выполняются обычным Playwright-кодом без обращений к LLM.

Для подключения к этому VPS нужен действующий SSH master с туннелем `127.0.0.1:15025 → VPS 127.0.0.1:50325`. Скрипт сам добавляет и убирает временный loopback-туннель к CDP-порту, полученному через API.

```sh
ADSPOWER_BASE_URL=http://127.0.0.1:15025 \
PROBE_SSH_CONFIG=/Users/ivanovivanivanovich/.ssh/content_factory_v14_config \
PROBE_SSH_SOCKET=/tmp/content-factory-v15-ssh.sock \
PROBE_EXPECTED_PROFILE_ID=k1j71gt4 \
./scripts/run-local.sh npm run probe:adspower
```

API-ключ читается из `.local/secrets/adspower-test.env`; значение не передаётся в аргументах командной строки. На том же хосте, где работает AdsPower, параметры SSH не нужны, а `ADSPOWER_BASE_URL` должен указывать на его loopback API.
