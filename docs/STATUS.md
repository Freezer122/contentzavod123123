# Состояние исходной поставки V1.0 — 17 ноября 2026

Обновление V1.1 описано в [UPDATE_V1_1.md](UPDATE_V1_1.md); изложенные ниже 40 проверок относятся к исходной поставке V1.0. В V1.1 новые правила режимов, цикла, CTA, кэша и аккаунтной атрибуции имеют приоритет.

Проект реализован и запускается локально. Производственный запуск на реальном Threads-аккаунте **ещё не принят**: для этого нужны ваши профили, авторизация, ключи и проверка текущего интерфейса.

## Выполненные проверки

- `npm run check`: форматирование, TypeScript, 40 пройденных автоматических тестов и production-сборка. Все проверки завершились успешно.
- Браузерные проверки выполнялись с настоящим Chromium на перехваченном локальном HTML, без обращений в Threads.
- Интеграционный тест выполнялся с настоящими PostgreSQL 18.6 и Redis 7.4.7, в изолированной случайной SQL-схеме и очереди. CI использует PostgreSQL 17 и Redis 7; запуск CI на GitHub отдельно не выполнялся.
- Настоящие команды `db:migrate` и `db:seed` применены в отдельной временной PostgreSQL БД: 24 прикладные таблицы плюс `_prisma_migrations`, четыре стиля.
- Через запущенный HTTP-сервер проверены: 10 демо-аккаунтов, меню Telegram, генерация, подтверждённая mock-публикация, идемпотентный повтор запроса, отмена, redirect 302 и CSV.
- Наблюдавшийся RSS Node.js в демо — около 196 MB. Это не оценка нагрузки десяти реальных профилей.
- npm audit после обновления зависимостей не обнаружил уязвимостей.

## Что не заявляется работающим без внешней приёмки

- Реальная отправка поста/CTA через текущий Threads UI и сохранение настоящих ссылок.
- Подключение к установленным AdsPower/Dolphin: проверены форма запросов/ответов, но их приложения отсутствуют в окружении.
- Качество перевода конкретной модели и её фактический биллинг.
- Доступность Insights для ваших аккаунтов. API ID определяется по permalink; недоступные показатели остаются NULL.
- Полнота Telegram-вступлений при длительных простоях и атрибуция прямых подписок. Неизвестный источник не угадывается.
- Выполнение systemd, Docker Compose, TLS, backup/restore и полного reboot на Ubuntu VPS: подготовлен код и инструкции, но сам VPS не предоставлен.

Единый Insights token поддерживает только разрешённые ему аккаунты. OAuth и отдельные зашифрованные токены для разных владельцев пока не реализованы. Для первичного сценария с вашими аккаунтами настройте разрешённый токен; при необходимости нескольких независимых токенов расширьте адаптер до промышленного запуска.

Демонстрация использует отдельное файловое хранилище и фиксированный тестовый генератор; она не подключается к вашим Threads-аккаунтам. Для нескольких процессов требуется production-режим. Тестовые данные и искусственные ссылки отмечены в интерфейсе.

Следующий практический шаг: заполнить production-конфигурацию по README и пройти приёмку **одного** авторизованного аккаунта с ручным подтверждением. Затем подключить остальные профили и проверить ресурсы при лимите одного исполнителя.
