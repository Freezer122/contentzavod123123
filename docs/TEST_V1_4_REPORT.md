## Условия успешного запуска

Первоначально клиент показывал сетевую ошибку. Дополнительно обнаружена отметка, что Threads 02 используется тем же аккаунтом на другом устройстве. Пользователь закрыл его там обычным способом; после обновления списка отметка занятости исчезла. Multi Device и принудительная разблокировка не включались.

Следующая попытка установила SunBrowser 155 и сообщила, что профиль можно открыть повторно. После повторного открытия браузер успешно запустился. Поэтому ранние снимки сетевой ошибки не являются итогом теста. Точная внутренняя причина первого общего сообщения о сети не установлена; конечного сбоя запуска больше нет.

## Ресурсы и область измерений

Числовой сборщик с интервалом 1 секунда запущен перед запуском AdsPower, после установки пакетов. Показатели RAM рассчитаны как `MemTotal - MemAvailable`; это отличается от столбца `used` некоторых версий `free`. CPU относится ко всему VPS, где уже работают другие сервисы.

- До AdsPower: RAM 1610,7 MiB, доступно 2301,1 MiB. Уже использовалось 888,1 MiB swap.
- Первый этап без браузера: 4056 замеров, пик RAM 2357,5 MiB, пик CPU 95,0%. Последний замер этого этапа: RAM 2259,8 MiB, доступно 1652,0 MiB, swap 890,3 MiB.
- Второй этап с реальным браузером: 1512 замеров; до запуска RAM 2273,4 MiB, доступно 1638,4 MiB. Пик RAM 2907,0 MiB (2,84 GiB); пик CPU всего VPS 100,0% суммарной мощности двух vCPU, включая установку ядра и запуск. Отдельный контрольный замер при работающем профиле: CPU 12,44%. Это нагрузка всего VPS, а не только SunBrowser.
- В рабочем снимке: один основной процесс SunBrowser, 22 процесса с учётом подпроцессов; браузер PSS 998,7 MiB, клиент AdsPower PSS 429,9 MiB, вся графическая сессия PSS 1527,8 MiB. PSS показывает пропорционально учтённую резидентную память; выгруженная в swap память в него не включена.
- После штатного закрытия профиля: RAM 1888,1 MiB, доступно 2023,7 MiB; процессов SunBrowser — 0. Пик использования существующего swap за второй этап — 1190,3 MiB.
- После нормального перезапуска интерфейс с профилями был подтверждён не позднее чем через 42,78 сек. Это измеренная верхняя граница до наблюдения интерфейса, а не точное время холодного старта. Первоначальное время старта точно не зафиксировано.
- Готовая страница Threads в запущенном браузере подтверждена не позднее чем через 77 сек после нажатия «Открыть» с установленным ядром. Это верхняя граница до первого наблюдения, а не непрерывный замер момента готовности. Время создания основного процесса сохранено отдельно из `/proc`.
- При первом подключении диск был заполнен на 100%, свободно около 293 MiB. Очищены повторно загружаемые кэши apt и npm; после установки клиента и его ядра оставалось около 977 MiB.
- По отдельному подтверждению пользователя выполнен `journalctl --vacuum-size=1G`: освобождено 3,0 GiB старых архивов; сохранено 992 MiB журналов. После этого было доступно около 4,0 GiB на диске. После установки SunBrowser 155 и завершения теста осталось 3368,1 MiB (около 3,3 GiB).
- Новый swap не создавался: на VPS уже есть около 2 GiB swap. Он не считается заменой RAM.

Проверка одного реального профиля на этих ресурсах прошла успешно. Сохраняется ограничение параллельности 1; два профиля и длительная работа не тестировались. Общая нагрузка включает сторонние сервисы и восстановленные вкладки существующего профиля.

## Сеть и изоляция

Проверена HTTPS-доступность корней `api-global.adspower.net` и `app-global.adspower.net`: HTTP 200, TLS проверяется штатно. Проверки выполнены как от root, так и от пользователя AdsPower. Исходящая политика IPv4 — ACCEPT. Эти проверки не доказывают исправность всех внутренних операций AdsPower и не устанавливают причину ошибки запуска.

AdsPower автоматически начал слушать `*:50325`, а при работе браузера появились служебные порты 20725, 20408 и 20409. Добавлены точечные правила INPUT для IPv4 и IPv6: соединения на эти четыре порта не через loopback отбрасываются. Правила восстанавливает включённый `content-factory-v14-api-guard.service`. Внешняя HTTP-проверка Local API завершилась таймаутом без ответа; счётчики firewall подтвердили отбрасывание пакетов. Простой TCP connect не использовался как доказательство доступности HTTP. Процессы по-прежнему слушают wildcard; изоляция обеспечивается firewall, а не изменением адреса bind. При будущих запусках необходимо проверять новые служебные порты: их номера могут меняться.

Xvfb запущен без TCP, с Xauthority. X11vnc слушает только loopback, использует временный пароль. Websockify/noVNC слушает `127.0.0.1:6088`; просмотр выполнялся через локальный SSH-туннель. PostgreSQL и Redis остались на loopback. Отладочный порт SunBrowser слушал `127.0.0.1` и закрылся вместе с профилем; подключения к нему не было. Состояния существующих nginx, PostgreSQL, Redis и Docker проверены: active.

AdsPower и лёгкая графическая сессия работают от отдельного непривилегированного пользователя `contentfactory`. Полная среда рабочего стола не устанавливалась. Графическая сессия диагностическая, без автоматического запуска после перезагрузки VPS. Приложение Content Factory, worker и планировщик на VPS не запускались; режим LIVE не включался.

## Ограничения и следующий шаг

Минимальный текущий платный уровень по официальной таблице — **Professional**, который включает Local API и синхронизацию между компьютерами. Покупка или активация пробного тарифа не выполнялись. Цена не фиксируется: динамическая таблица не загрузила сумму. Успешное восстановление сессии в этом тесте не означает, что регулярная синхронизация теперь включена в Free.

После получения официальных прав API необходимо получить список профилей и проверить соответствие точного имени Threads 02 внутреннему ID `k1j71gt4`, запустить только этот профиль и подключить существующий `AdsPowerProvider`/Playwright через официальный endpoint. Ручной тест не заменяет эту проверку интеграции. Подмена профиля, сброс cookies или использование обычного Chromium не требуются.

Фактический интерфейс Threads в этом профиле немецкий: «Neuer Thread», «Posten». Существующий файл селекторов с английскими и русскими вариантами через CDP не проверялся. Перед LIVE необходимо проверить селекторы на этом же профиле с официально доступным API.

Публикаций, комментариев, изменений прокси и сбросов cookies не выполнялось. Тестовый пост пока не подготовлен: требуемое подключение Playwright ещё недоступно. До отдельного подтверждения пользователя ничего не отправлять. После теста профиль закрыт штатно; сам клиент AdsPower оставлен авторизованным.
