# Браузерные профили

По умолчанию используйте DRY_RUN: `npm run dry-run -- OK saved-profile-Threads-02`. На Threads 02 (`k1j71gt4`, `@beh4ppy01`) успешно выполнены Playwright/API/CDP-проверки и первая реальная публикация поста с CTA. В hotfix V1.5 подтверждение сначала использует post-submit интерфейс и собственный permalink, опрос выполняется каждые 2,5 секунды с резервным чтением профиля. Постоянный worker остаётся DRY_RUN, новые публикации требуют отдельного разрешения. Текущая приёмка и ограничения — в [отчёте V1.5](HOTFIX_V1_5_REPORT.md); первая отправка — в [отчёте публикации](FIRST_PUBLICATION_REPORT.md). Ранее принятый [LIVE_READ_ONLY](PLAYWRIGHT_TEST_REPORT.md) сохранён как история.

Установите AdsPower либо Dolphin Anty на тот же хост, где работает исполнитель. Приложение браузера должно быть запущено и авторизовано в графической сессии. Контейнеры PostgreSQL и Redis не предоставляют эту сессию.

## AdsPower

1. Включите Local API, укажите `ADSPOWER_BASE_URL=http://127.0.0.1:50325` и при необходимости `ADSPOWER_API_KEY`.
2. Через меню «Аккаунты → Профили браузеров» получите ID существующего профиля. Авторизуйтесь в Threads внутри него вручную.
3. Добавьте аккаунт:

```text
/account {"username":"my_trader","name":"Мой трейдер","provider":"ADSPOWER","externalId":"PROFILE_ID","styleId":"style-1"}
```

4. Нажмите «Проверить доступность всех», затем включите аккаунт.

Адаптер использует `/api/v1/user/list` с пагинацией, `/api/v1/browser/start`, `/api/v1/browser/active` и `/api/v1/browser/stop`. Для Playwright используется `data.ws.puppeteer`. Каждый сеанс закрывается в `finally`.

## Dolphin Anty

Задайте `DOLPHIN_BASE_URL=http://127.0.0.1:3001` и `DOLPHIN_API_TOKEN`. Порт проверьте в Health приложения. Токен отправляется локальному `/v1.0/auth/login-with-token`. Запуск: `/v1.0/browser_profiles/{id}/start?automation=1`; остановка: `/v1.0/browser_profiles/{id}/stop`. CDP строится из `automation.port` и `automation.wsEndpoint`.

Список профилей запрашивается через официальный Remote API `/browser_profiles/list-cursor`. Переходы пагинации разрешены только внутри того же API origin. Если cursor-пагинация не доступна для аккаунта, добавляйте ID из приложения вручную и обратитесь к документации/поддержке Dolphin. Для запуска требуется тариф с доступом к автоматизации.

## Проверка селекторов

`fixtures/threads-selectors.json` уточнён по реальному интерфейсу Threads 02 на VPS 19 ноября 2026. Проверены аккаунт, создание черновика, ввод текста, кнопка Posten до барьера отправки, контейнеры постов и открытие редактора ответа. Первая реальная публикация поста и CTA с изображением подтверждена отдельным чтением собственных URL. После обнаруженной задержки отображения подтверждение дополнено повторным чтением страницы без повторного submit. Подробности и оставшиеся ограничения — в [отчёте первой публикации](FIRST_PUBLICATION_REPORT.md).

Настройте `loggedIn`, `identity`, `create`, `dialog`, `editor`, `submit`, `ownPost`, `postLink`, `reply`, `replySubmit`, `comment`, `challenge`, `restricted`. Селектор идентичности обязан содержать `{username}`; он проверяет текущий аккаунт. Используйте точные роли и доступные имена элементов. Не ослабляйте проверку уникальности ради прохождения сценария.

Проверка результата требует новый URL **внутри собственной публикации с соответствующим текстом**. Неоднозначный результат переводит задачу в «Требуется проверка». Сбой после начала отправки не вызывает автоматический повтор. При ошибке сохраняются PNG и технический JSON в `artifacts/`; они могут содержать личные данные интерфейса, поэтому доступны только локально.

Проверки личности, капча и ограничения останавливают аккаунт. Пройдите их вручную в официальном интерфейсе. Затем проверьте аккаунт, включите его и возобновите безопасную задачу командой `/resume_job ID`. Для неизвестного результата сначала найдите публикацию вручную. Команда `/verify ID URL` фиксирует найденный пост с записью в аудит. Она не выполняет новую отправку.

Не используйте один профиль одновременно вручную и через завод. Если профиль уже запущен, исполнитель откажется его использовать. В production запрещён Mock-профиль при добавлении аккаунтов.

Официальные источники: [AdsPower: запуск](https://localapi-doc-en.adspower.com/docs/FFMFMf), [остановка](https://localapi-doc-en.adspower.com/docs/DXam94), [Dolphin: Local API](https://docs.dolphin-anty.com/en/api/basic-automation-dolphin-anty), [Dolphin: справочник API](https://docs.dolphin-anty-cdn.com/index.html).
