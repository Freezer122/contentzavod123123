# V1.15 — Generation hotfix

Дата: 21 ноября 2026, МСК. События ниже указаны в UTC. Продолжает V1.14 без замены браузерной интеграции, БД, бюджетов и ручных разрешений.

## Причина

Задача `c1fc7049bcf995a0e5316c3f49e476cf` не зависла. Создана 20 ноября 17:08:11.193, исполнение 17:08:17.439–17:08:19.684, доставка 17:08:21.601. Сохранены draft `445dc613-46c4-4019-93f0-fd2286b37881`, запрос `1d5e1be2-1df9-4d1c-8efd-60719ed07aa4`, кэш и Telegram receipt. Terra: 288 input / 25 output, $0.000413. Ответ: «когда всё по плану, даже стоп воспринимается не как провал, а как часть сделки».

Повторная кнопка возвращала существующую завершённую задачу, но интерфейс обещал новую генерацию вместо немедленного показа результата. Массовый отбор учитывал только NEW: из первоначальных 19 кандидатов три NEW не проходили дату/строгую тематику; подходящие DRAFTED уже имели ответы. Причина нуля — фильтры и готовые черновики, а не бюджет.

Старый DOM-extractor включал автора, дату, Übersetzen и счётчики в текст. Старый callback генерации также опирался на глобальный FSM вместо ID кандидата.

## Изменения

- Обычная генерация идемпотентна по аккаунту/кандидату; повторные клики показывают существующий результат без нового LLM. Активные перегенерации объединяются.
- Новые кнопки несут ID кандидата. Непривязанная старая кнопка требует открыть актуальную карточку.
- Массовый отбор показывает найдено/доступно/готово/в обработке/отклонено по дате и тематике/заблокировано/создано и конкретные причины нуля.
- Очередь и результаты сохраняются независимо от Telegram FSM. Доставка имеет отдельный статус, message ID, backoff; ошибка одной доставки не блокирует остальные.
- При восстановлении сначала проверяются кэш и сохранённый receipt. UNKNOWN не вызывает новую платную генерацию.
- Общий семантический DOM-reader извлекает тело публикации отдельно от метаданных. Старый исходник перечитывается READ_ONLY по точному permalink до нового запроса; исходная версия архивируется. Готовые старые черновики доступны бесплатно.

Файлы: `src/content/jobs.ts`, `src/content/service.ts`, `src/engagement/discovery.ts`, `src/engagement/browser.ts`, `src/engagement/service.ts`, `src/bot/generation.ts`, `src/bot/extensions-v18.ts`, `src/bot/extensions-v113.ts`, `scripts/acceptance-v115.ts`, `scripts/inspect-v115.ts`, соответствующие deployment scripts и тесты.

## Реальная приёмка

Владелец сообщил о падении явно запрошенной перегенерации старого исходника. После исправления READ_ONLY-перечитывания возобновлена только его последняя задача `4f78157b9fcbac8467813d4e0ba02461`; завершена/доставлена 19:55:28.364, Telegram message 412. Вторая историческая неудачная попытка не повторялась.

Владелец подтвердил показ готового ответа при повторном нажатии и объяснение нуля. Реальный `REPLY_SELECTION` 20:12:18.557 создал три задачи, доставленные как messages 422, 423, 424 в 20:12:24.721 / 20:12:30.747 / 20:12:32.833. Следующая выборка создала 0: все четыре доступных кандидата уже имели черновики. Отдельный CLI-check того же backend в 20:20:45 также создал 0; он не выдаётся за Telegram callback.

Пять новых запросов этапа A: 2717 input / 131 output, $0.003372. Повторный просмотр c1fc и нулевые выборки не расходовали LLM.

## Границы безопасности

Тесты и acceptance scripts не нажимали публикацию. Во время проверки владелец отдельно воспользовался действующим MANUAL_LIVE: reply job `7bdf32f9-c296-4545-aa5b-73f7b6abe754`, Telegram action 19:59:12.369, permalink `Df-dn4zAoQg`; затем post job `aec78b46-51fd-4079-a889-730588ea1835`, Telegram action 20:54:15.123, permalink `Df-j5orgn8P`, CTA `Df-j8Nsgpto`. Это отдельные подтверждённые ручные действия, а не результаты непубликующего теста. Неудачная повторная ручная команда остановлена минимальным интервалом, без отправки.

Старые опубликованные записи сохранены. Старая PAUSED-задача с ожидающим CTA не возобновлялась. Thread 01 не запускался. Глобальные автоматические режимы остались DRY_RUN, factory PAUSED, MANUAL_LIVE сохранён.
