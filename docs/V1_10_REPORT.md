# Content Factory V1.10 — публикации и engagement

Дата: 20 ноября 2026. Текущий VPS: `48.102.129.89`. Активный релиз: `/opt/content-factory/releases/20261120-v110-fixes`. Проект и production-БД не переносились и не пересоздавались. Перед переключением создан `KEEP-before-v110` backup. Новых миграций схемы нет.

## Что установлено о старом молчании

В production-аудите есть последовательность: `publication:ACCOUNT_SPECIFIC` → `assign:threads02` в 21:57:06 UTC 19 ноября → `TEXT_INPUT` в 21:57:20. После этого исходник в `source_contents` не появился, FSM остался `step=source`, `activeAccountId=threads02`, `assignments={}`. В этот момент LLM не вызывалась: в `ai_requests` были только две проверки V1.9. Поэтому объяснять этот инцидент долгим Sol-запросом нельзя.

**Точную ветку, которая обработала именно то старое сообщение, доказать по старым журналам невозможно.** Они не сохраняли тип update, длину, состояние второго FSM и этап входа в SourceLibrary. `TEXT_INPUT` тогда записывался также для сообщений без `message.text`. Пользователь уточнил, что отправлял обычный текст; это уточнение учтено, версия с обязательным `.txt`-вложением не принимается за установленную причину. Исходный проблемный текст не предоставлен; запрос на него оставлен пользователю. Не следует выдавать найденные ниже дефекты за доказанную единственную причину того исторического сообщения.

В коде найдены и исправлены проверяемые проблемы:

- выбор исходников показывал только ACTIVE-аккаунты, хотя подготовка должна работать и при PAUSED;
- сохранённый материал не назначался аккаунту до дополнительного подтверждения прав, поэтому счётчик назначений оставался нулевым;
- два FSM (`flow-*` и `v18-flow-*`) могли перехватывать ввод после смены сценария;
- обычные текстовые вложения, другие типы сообщений и редактирование старого сообщения не получали понятного ответа;
- ошибка доставки уведомления могла прервать запись исходной ошибки;
- генерация и поиск выполнялись с ожиданием внутри обработчика update, удерживая polling на время внешней операции;
- промпт описывал только английский исходник, хотя сервис не запрещал русский.

Теперь `BOT_STAGE` фиксирует received/handled/failed/source_saved/telegram_delivery_failed, update ID, тип, размер, шаг и идентификаторы. Исходный текст и секреты в эту диагностику не включаются. В новом реальном тесте update `657077896` прошёл этапы получения текста, сохранения и подтверждения: **3310 символов, Threads 02**.

## Почему не было реплаев

На момент диагностики фактические значения были:

| Проверка                    | Состояние                                              |
| --------------------------- | ------------------------------------------------------ |
| factoryPaused               | true                                                   |
| Threads 02                  | ACTIVE, включён пользователем                          |
| BROWSER_EXECUTION_MODE      | DRY_RUN                                                |
| ENGAGEMENT_EXECUTION_MODE   | DRY_RUN                                                |
| Engagement enabled / likes  | true / true, настройки пользователя сохранены          |
| Ответы / интервал / поиски  | 3 в сутки / 60–180 минут / 3 сессии в сутки            |
| Одобренный ответ            | один QUEUED, с 19 ноября 22:06:40 UTC                  |
| OpenAI                      | ключ присутствует, модели доступны, бюджет не исчерпан |
| PostgreSQL / Redis / worker | доступны, службы запущены                              |

**Автоматическую очередь останавливала глобальная PAUSED, а реальную отправку дополнительно запрещали оба DRY_RUN-флага.** Включение engagement само по себе не снимало эти ограничения. Старый интерфейс показывал общий режим, но не объединял его с глобальной паузой и состоянием очереди.

Дополнительно старый ручной поиск требовал интервал `24 часа / sessionsPerDay` — при трёх сессиях это восемь часов, независимо от интервала между взаимодействиями 60–180 минут. В журнале сохранились две ошибки SEARCH_INTERVAL. Старый поиск расходовал попытку до открытия браузера; nextSearchAt отсутствовал. Автоматический цикл искал кандидатов, но сам не генерировал ответы: для этого и для одобрения нужны отдельные команды.

В старых журналах фоновой аналитики/когорт также обнаружены отдельные сериализационные конфликты PostgreSQL lease-транзакций. Службы не останавливались; это не доказательство ошибки сохранения исходника. Рабочие модули аналитики не переписывались.

## Исправления сценария публикации

После приёма текста исходник сразу сохраняется в PostgreSQL и назначается аккаунту. Карточка подтверждает имя аккаунта, число символов, успешное сохранение, состояние подготовки и число назначений. Кнопки: подготовить, изменить, посмотреть, удалить, назад к аккаунтам. Права на публикацию подтверждаются отдельно и по-прежнему проверяются Scheduler.

Предел — 20 000 символов. Для больших исходников поддержан UTF-8 `.txt` до 80 КБ. Ошибки размера и кодировки объясняются явно. Русский текст переписывается по-русски, английский адаптируется на русский. Версия промпта изменена; старый кэш сохранён, новая инструкция имеет свой ключ.

Подготовка создаёт постоянную задачу `generation-task-*`. Worker исполняет её отдельно от Telegram polling; бот немедленно показывает «Генерирую», затем доставляет предпросмотр с одобрением, перегенерацией, редактированием и отклонением. Прежние оценки качества сохранены. Повторное нажатие подготовки использует ту же задачу/результат, дополнительного LLM-запроса нет.

Фабрика/аккаунт PAUSED и DRY_RUN не мешают хранению, генерации и предпросмотру. Одобрение текста не создаёт publishing job; реальная отправка требует отдельного подтверждения. Это относится также к старой кнопке одобрения из истории чата. DRY_RUN блокирует финальную отправку. Удаление исходника отменяет ожидающие генерации; во время RUNNING удаление блокируется до результата. Использованные исходники сохраняются для истории.

QUEUED-задачи и FSM переживают рестарт. Прерванная RUNNING-генерация становится NEEDS_REVIEW, платного повтора нет. FAILED доставляется пользователю с понятным сообщением; повтор возможен отдельной явной кнопкой. Неподтверждённый расход OpenAI UNKNOWN продолжает блокировать новые LLM-запросы до сверки.

## Engagement и расписание

Разделены ручной READ_ONLY-поиск, подготовка Terra и исполнение одобренных действий. Поиск без публикации разрешён при PAUSED/DRY_RUN и не вызывает LLM. Генерация запускается отдельно, после неё ответ остаётся DRAFT. В DRY_RUN worker не превращает одобренные задания в реальные ответы или лайки.

`engagement-schedule-threads02` хранит nextSearchAt, lastSearchAt, lastAttemptAt, статистику и ошибку. После рестарта расписание восстанавливается. После успешного поиска следующий старт рассчитывается от фактического времени; пропущенные интервалы не выполняются пачкой. Неудачное открытие браузера не расходует успешную дневную поисковую сессию; автоповтор поиска получает паузу 15 минут. Ручной поиск может обойти ожидание интервала, но соблюдает дневной лимит.

Сохранены allowlist профилей, один browser-slot, приоритет собственных постов/CTA, проверка дубликатов и UNCERTAIN. Повторная генерация ответа одному кандидату возвращает существующий неотклонённый результат. Чужие сессии не заимствуются и не закрываются. Thread 01 не использовался.

Экран «Причины остановки» показывает глобальную паузу, аккаунт, включение поиска, доступность генерации, LLM/бюджет, эффективный режим отправки, heartbeat очереди, прошлый и следующий поиск, кандидатов, ожидание одобрения, одобренную очередь, дневные отправки и ошибки. Времена отображаются в Europe/Moscow, дневные лимиты явно обозначены как UTC.

После приёмки следующий поиск сохранён на **20 ноября, 20:03:26 Europe/Moscow** (`17:03:26 UTC`). До снятия PAUSED автопоиск ожидает; интерфейс объясняет причину. Фабрика остаётся на паузе, автоматическое включение LIVE не выполнялось.

## Приёмка на VPS и Telegram

### A — настоящий входящий текст

Через открытый Telegram Desktop в правильный бот `@ChadTrafficTestosteroneBot` отправлено обычное многострочное сообщение на **3310 символов**. Визуально получена карточка «Исходник сохранён для Threads 02», размер, PostgreSQL, назначение и все пять требуемых кнопок. PostgreSQL и polling подтвердили получение. Это авторский русский тестовый исходник; потерянный исторический текст им не подменяется.

Затем реально перезапущены bot и worker. Сохранённое назначение и исходник восстановлены.

### B — Sol

Тот же обработчик кнопки подготовки вызван служебным callback-тестом; для синтетического callback замокан только answerCallbackQuery, потому что Telegram не принимает выдуманный query ID. Сам исходник пришёл через настоящий polling; очередь, PostgreSQL, OpenAI и доставка предпросмотра — настоящие. Физическое нажатие inline-кнопки в Telegram Desktop этим служебным вызовом не заявляется как проверенное.

Получен и доставлен в Telegram неодобренный предпросмотр:

> пока цена стоит на месте, торговый план кажется простым. стоит ей резко двинуться - и свои же правила легко забыть
>
> поэтому до входа лучше записать две вещи: при каких условиях идея больше не работает и сколько ты готов потерять на этой сделке. потом смотришь не на плюс или минус, а на то, держался ли ты плана

### C — поиск и Terra

Выполнен свежий поиск реальным Playwright/AdsPower при PAUSED и DRY_RUN: **найдено 9 публикаций, подходят 6, новых сохранено 6**. До новой генерации в базе было два неотклонённых черновика; счётчики получены из БД, а не из примера ТЗ. Всего после поиска — 13 кандидатов.

Подготовлен один новый черновик Terra к существующей [публикации Threads](https://www.threads.com/@qyr.balasy/post/DCtkaXFCgrd), доставлен в Telegram и оставлен DRAFT:

> налоговые обязанности зависят от страны налогового резидентства, вида дохода и того, удерживает ли налог брокер. даже если брокер выступает налоговым агентом, стоит проверять отчёты: по отдельным доходам может потребоваться самостоятельная декларация

Это результат тестовой генерации, содержание не проверялось как налоговая консультация и не публиковалось.

### D — причины остановки

Настоящим Telegram API доставлен экран диагностики: завод PAUSED, аккаунт ACTIVE, отправка DRY_RUN; один прежний одобренный ответ ожидает исполнения, один новый ответ ожидает одобрения, отправлено ответов/лайков сегодня — 0/0. Сохранённый прежний QUEUED-ответ не отменялся и не отправлялся.

## Что осталось до LIVE

Завод остаётся PAUSED, publishing/engagement — DRY_RUN, изменение профиля запрещено. Настройки engagement и ACTIVE-статус аккаунта, заданные пользователем, сохранены. Для LIVE нужны отдельные подтверждения конкретных текстов/действий, проверка прав на исходник, явная настройка LIVE и снятие паузы. Предыдущий одобренный QUEUED-ответ перед включением необходимо отдельно сверить: он сохранён с прошлого дня. Автоматически его не подтверждать повторно. Точная историческая причина исчезнувшего исходника остаётся недоказанной без исходного сообщения; новый сценарий сохранения, восстановления и подготовки проверен на настоящем входящем Telegram-сообщении.
